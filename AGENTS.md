# MemoryBox - инструкции для агентов

## Назначение проекта

MemoryBox - локальное однопользовательское приложение для визуального хранения воспоминаний. Пользователь создаёт доски для произвольных периодов (от нескольких дней до месяцев) и размещает на бесконечном холсте связанные между собой воспоминания.

Это не социальная сеть, не облачный сервис и не замена фототеки. Приоритеты: личный характер, локальное хранение, ясный Canvas-сценарий и отсутствие функций вне явно запрошенной области.

## Термины

- **Доска (`Board`)** - холст для одного периода. У неё есть название, `start_date` и `end_date`.
- **Нода / узел (`MemoryNode`)** - объект на Canvas. Бывает карточкой (`note`, `media`, `track`) или объектом без карточки (`canvas_text`, `canvas_image`).
- **Папка (`folder`)** - запланированный объект Canvas, а не доска (`Board`). Она визуально следует компьютерной стилистике и объединяет другие объекты этой же доски. При открытии связанные объекты должны анимированно «вылетать» из папки на их сохранённые позиции на холсте; при закрытии — возвращаться обратно. Реализация ещё не начата: в отдельной задаче нужно определить формат хранения состава папки и состояния открытия, соблюдая правила совместимого обновления БД.
- **Заметка (`note`)** - текстовая нода с необязательным заголовком и текстом.
- **Медиакарточка (`media`)** - нода с одной или несколькими загруженными фотографиями и видео. Файлы описываются сущностями `MediaAsset`.
- **Музыка (`track`)** - нода с двумя режимами: отдельный трек или плейлист. Метаданные хранятся в `TrackData`; у плейлиста есть `playlist_items`.
- **Текст (`canvas_text`)** - объект без карточки. Текст и его стили (шрифт, размер, начертание, выравнивание и цвет) хранятся в `MemoryNode.object_data`.
- **Изображение (`canvas_image`)** - объект без карточки с одним загруженным PNG-файлом через `MediaAsset`.
- **Обложка** - изображение музыкальной ноды. Обложки, выбранные через Spotify или заданные внешней ссылкой, скачиваются в локальный volume в `uploads/covers`.
- **Связь / ребро (`MemoryEdge`)** - линия между двумя нодами Canvas.
- **Timeline** - временная шкала внизу доски. Она показывает до пяти меток для нод с `temporal_date` на конкретный день, но не управляет их позицией автоматически.
- **Слои** - порядок перекрытия нод, сохранённый в `MemoryNode.z_index`.

## Архитектура и данные

- Frontend: React + TypeScript + Vite + Tailwind, Canvas на `@xyflow/react`.
- Backend: FastAPI + Pydantic + SQLAlchemy.
- Метаданные: SQLite.
- Загруженные медиа, изображения на холсте и локальные обложки: mounted volume, отдельно от SQLite. Файлы нельзя хранить в SQLite BLOB.
- Frontend обращается к файлам только через backend (`/media/...`), а не к файловой системе напрямую.
- Основные точки: `frontend/src/App.tsx`, `frontend/src/MemoryCard.tsx`, `frontend/src/Editor.tsx`, `frontend/src/styles.css`, `backend/app/main.py`, `backend/app/models.py`, `backend/app/schemas.py`.

## Правила изменения базы данных

1. Перед изменением моделей, таблиц, полей, типов, ограничений или формата JSON **сначала спросить пользователя**, можно ли очистить существующую SQLite БД и локальные данные. Не предполагать, что очистка разрешена, даже если проект локальный.
2. Явно объяснить, что именно будет потеряно: доски, ноды, связи, позиции, метаданные, медиафайлы или локальные обложки.
3. Если пользователь не разрешил очистку, реализовать обратимо-совместимое обновление: сохранить существующие данные и добавить безопасную эволюцию схемы. Не выполнять `rm`, `git reset`, удаление volume или SQLite-файла без явного согласия.
4. Если пользователь разрешил очистку, подтвердить точный объём очистки: только SQLite или также mounted volume с `uploads`.
5. Не добавлять миграции «на всякий случай». Для этого проекта допускается изменить `initialise()` в backend, но только при совместимом обновлении уже существующей БД.

## Рабочий процесс

- Перед правками осмотреть текущую реализацию и не откатывать пользовательские изменения.
- После frontend-изменений запускать production-сборку (`npm run build` через Docker Compose).
- После backend-изменений запускать `pytest` в backend-контейнере.
- Не коммитить SQLite-файлы, `.env`, uploaded media или generated thumbnails/covers.
- Сообщать пользователю, какие части были изменены и какой тест или сборка прошли.
